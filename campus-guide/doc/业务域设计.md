# 业务域设计

> 当前技术栈：Spring Boot 3.5.14 + JDK 21 + MyBatis-Plus 3.5.11 + Spring AI 1.0.7 + Redis + Qdrant + MySQL + 阿里云 OSS/NLS
>
> 本文只描述当前定档业务域、边界和数据模型。旧的独立路线节点、路线连线、独立围栏表不再作为当前模型

## 2. 核心边界

### 2.0 当前单景区上下文与未来多租户

> 重点约束：当前阶段不实现多租户和多景区切换，默认只服务一个演示景区“桃花源”

当前代码允许保留 `scenic_area_id` 字段和默认景区兜底，但不要把默认景区写成不可替换的业务规则。地图、路线、知识库、游客会话、数字人配置和运营分析都必须保留景区维度。

未来多租户按“平台 -> 运营公司/租户 -> 景区/项目”设计。租户是运营主体，景区是租户下的业务资源。一家公司可能管理多个景区，因此 `scenic_area` 不能承担租户语义。

未来景区切换是后台全局业务上下文切换，不属于地图工作台内部功能。切换景区会整体影响地图草稿、上线地图、预置路线、知识库资料、数字人配置、游客会话和运营分析。

### 2.1 scenic 域

scenic 域维护“有什么”和“在哪里”：

- `scenic_area`：单景区基础资料和默认地图中心
- `scenic_spot`：景点业务对象，包含标注点和 polygon 围栏
- `scenic_facility`：服务点业务对象，包含点位坐标
- `scenic_tag` / `scenic_spot_tag`：景点标签
- `scenic_map_draft`：后台地图工作台主数据源，以 payload 保存当前草稿的景点、服务点、内部地图点、路线段和预置路线

地图工作台不再把 `scenic_spot`、`scenic_facility`、`route_endpoint`、`route_segment` 作为保存主链路。后台编辑、发布校验和游客端地图读取都以 `scenic_map_draft.payload` 为准。

### 2.2 route 域

route 域维护“怎么走”和“为什么推荐”：

- `route_endpoint`：内部地图点，只保存空白端点或分叉端点，不作为运营资产展示
- `route_segment`：路线段，连接 `SPOT`、`FACILITY`、`ENDPOINT` 三类端点
- 预制路线：运营编排游览目标序列，最终由路线段图谱支撑推荐和高亮
- AI 路线推荐：读取景点、服务点、路线段属性和游客偏好，生成可解释路线

路线段是业务对象，承载长度、耗时、类型、收费、拥挤度和 AI 描述。编辑折线不会隐式拆分路线，端点变更必须由运营显式操作。

### 2.3 tourist 域

tourist 域维护导览业务状态：

- 会话生命周期
- 游客位置上报
- 基于景点 polygon 的围栏进入/停留/离开判定
- 当前路线进度
- 自动播报防重和日志

围栏触发日志可以继续使用“围栏”语义，但围栏来源是景点 polygon，不是独立围栏资产表。

## 3. 景区资产域模型

### 3.1 scenic_area

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| name | VARCHAR | 景区名称 |
| description | VARCHAR/TEXT | 景区描述 |
| center_longitude | DECIMAL | 地图中心经度 |
| center_latitude | DECIMAL | 地图中心纬度 |
| default_zoom | INT | 后台地图默认缩放 |
| status | TINYINT | 1 启用，0 停用 |
| created_at / updated_at / deleted | 通用字段 | 创建、更新、逻辑删除 |

### 3.2 scenic_spot

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| scenic_area_id | BIGINT | 所属景区 |
| name | VARCHAR | 景点名称 |
| description | VARCHAR/TEXT | 景点描述 |
| label_longitude | DECIMAL | 标注点经度 |
| label_latitude | DECIMAL | 标注点纬度 |
| fence_polygon | JSON | 景点多边形围栏，坐标数组 |
| status | TINYINT | 1 启用，0 停用 |
| created_at / updated_at / deleted | 通用字段 | 创建、更新、逻辑删除 |

规则：

- 景点标注点默认位于 polygon 几何中心
- 编辑 polygon 后同步更新标注点
- 拖动景点标注点时 polygon 整体平移
- 删除景点时必须提示并级联删除关联路线段

### 3.3 scenic_facility

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| scenic_area_id | BIGINT | 所属景区 |
| name | VARCHAR | 服务点名称 |
| facility_type | VARCHAR | 服务点类型，如 TOILET、PARKING、SERVICE、SHOP |
| description | VARCHAR/TEXT | 服务点描述 |
| longitude | DECIMAL | 经度 |
| latitude | DECIMAL | 纬度 |
| status | TINYINT | 1 启用，0 停用 |
| created_at / updated_at / deleted | 通用字段 | 创建、更新、逻辑删除 |

规则：

- 服务点是点位对象，没有 polygon
- 拖动服务点时关联路线端点跟随
- 删除服务点时必须提示并级联删除关联路线段

## 4. 路线导览域模型

### 4.1 route_endpoint

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| scenic_area_id | BIGINT | 所属景区 |
| name | VARCHAR | 内部名称，可为空 |
| endpoint_type | VARCHAR | MAP_POINT 或 JUNCTION |
| longitude | DECIMAL | 经度 |
| latitude | DECIMAL | 纬度 |
| status | TINYINT | 1 启用，0 停用 |
| created_at / updated_at / deleted | 通用字段 | 创建、更新、逻辑删除 |

规则：

- 只保存空白地图端点或分叉点
- 不为每个景点或服务点生成 endpoint
- 不在后台资产列表中作为运营对象展示
- 保存路线时才物化 endpoint，取消编辑不得留下孤立 endpoint
- 删除或更新路线后清理不再被引用的 endpoint

### 4.2 route_segment

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| scenic_area_id | BIGINT | 所属景区 |
| name | VARCHAR | 路线名称 |
| from_type | VARCHAR | SPOT、FACILITY、ENDPOINT |
| from_id | BIGINT | 起点对象 ID |
| to_type | VARCHAR | SPOT、FACILITY、ENDPOINT |
| to_id | BIGINT | 终点对象 ID |
| middle_points | JSON | 中间路径点数组，只表示几何形状 |
| length_meter | INT | 路线长度，米 |
| duration_min | INT | 预计耗时，分钟 |
| route_type | VARCHAR | 路线类型，默认 WALK，可存运营自定义类型 |
| is_paid | TINYINT | 1 收费，0 免费 |
| ai_note | VARCHAR/TEXT | 给 AI 的路线描述，如坡、桥、临水、缆车 |
| crowd_level | TINYINT | 拥挤等级 1-5 |
| status | TINYINT | 1 启用，0 停用 |
| created_at / updated_at / deleted | 通用字段 | 创建、更新、逻辑删除 |

规则：

- 路线头尾端点不能相同
- 中间路径点不参与吸附和算路节点连接
- 一条路线确定后承载业务属性，不能因几何编辑被隐式拆成两条
- 若要分叉，运营主动创建多条路线，共用同一个内部 endpoint

|--------|--------|------|
| scenic-fence-default-radius | 50 | 新建景点 polygon 的默认近似半径 |

| 配置键 | 默认值 | 说明 |

## 6. 当前后台工作流

1. 运营在地图工作台维护景点、服务点和路线
2. 点击保存草稿后，后端保存当前工作台数据
3. 发布页基于已保存草稿运行校验
4. 校验通过后将目标地图草稿切换为 `ONLINE`
5. 游客端只读取当前 `ONLINE` 地图草稿，不读取普通 `DRAFT` 草稿和浏览器未保存编辑态

## 7. 当前约束

- 后台真实地图使用高德 JSAPI，游客端展示手绘地图和业务路线
- 景点 polygon 是自动讲解围栏来源
- 内部地图点不是运营资产
- 路线端点只允许绑定景点、服务点或内部地图点
- 中间路径点只负责路线形状
- 不保留旧的独立节点、连线、围栏管理页
