# 路线设计文档

> 当前定档：路线不是导航系统，而是 AI 数字人导游理解景区空间关系、推荐游览路径、解释推荐理由和支撑自动讲解的基础能力
>
> 本文只描述当前模型：景点、服务点、内部地图点、路线段、中间路径点

## 1. 核心结论

路线是一段可通行关系：

```text
路线段 = 起点 + 终点 + 中间路径点 + 路线属性
```

| 概念 | 定义 | 是否运营独立管理 |
|------|------|------------------|
| 景点 | 游客要游览和听讲解的业务目标，包含标注点和 polygon 围栏 | 是 |
| 服务点 | 卫生间、游客中心、停车场、商店等点位目标 | 是 |
| 内部地图点 | 空白路线端点或分叉点，仅用于连接路线 | 否 |
| 路线段 | 两个端点之间的一条路，承载路线属性 | 是 |
| 中间路径点 | 路线折线形状控制点 | 否 |

路线端点只允许三种引用：

```text
SPOT
FACILITY
ENDPOINT
```

其中 `ENDPOINT` 指内部地图点。

## 2. 做与不做

必须做：

| 能力 | 说明 |
|------|------|
| 手动画路线 | 运营从起点连续打点到终点，生成曲线路线 |
| 路线属性配置 | 长度、耗时、类型、是否收费、拥挤度、AI 描述 |
| 景点联动 | 移动景点时，关联路线端点跟随 |
| 服务点联动 | 移动服务点时，关联路线端点跟随 |
| 级联删除 | 删除景点或服务点时提示并删除关联路线 |
| 分叉连接 | 支持 A -> J -> B/C/D |
| 端点吸附 | 创建路线或显式重设端点时吸附到景点、服务点或内部地图点 |
| 发布校验 | 校验 polygon、路线端点、孤立内部点、路线属性完整性 |

明确不做：

| 不做能力 | 原因 |
|----------|------|
| 把内部地图点做成运营资产 | 会把后台复杂度推向 GIS 导航系统 |
| 路线连接到另一条路线的中间路径点 | 会破坏原路线独立性和业务属性 |
| 几何编辑时自动拆分路线 | 路线是业务对象，不能隐式拆分 |
| 导航级转弯提示 | 项目定位是 AI 导游，不是替代专业导航 |
| 独立围栏管理页 | 当前围栏来源是景点 polygon |

## 3. 简单路线

最简单情况：

```text
A 景点 -> B 景点
```

运营操作：

1. 点击路线工具
2. 点击 A 景点作为起点
3. 在地图上连续打中间路径点
4. 点击 B 景点作为终点
5. 填写长度、耗时、类型、收费、拥挤度和 AI 描述
6. 保存路线

内部结构：

```json
{
  "from": { "type": "SPOT", "id": 1 },
  "to": { "type": "SPOT", "id": 2 },
  "middlePoints": [[30.2524, 120.1380], [30.2530, 120.1400]],
  "lengthMeter": 520,
  "durationMin": 8,
  "routeType": "WALK",
  "paid": false,
  "aiNote": "平整石板路，适合亲子和老人慢行",
  "crowdLevel": 1,
  "status": 1
}
```

中间路径点只负责绘制曲线，不参与端点吸附和图连接。

## 4. 多路线共用景点

一个景点 A 可以是多条路线端点：

```text
A -> B
A -> C
A -> D
```

删除 A 时必须展示影响范围：

```text
删除景点 A 将同时删除 3 条关联路线：
A - B
A - C
A - D
是否继续？
```

移动 A 时，三条路线的 A 端都跟随移动，中间路径点保持不动。

## 5. 分叉路线

实际路线可能从 A 走到某个分叉点，再分别去 B、C、D：

```text
        -> B
A -> J -> C
        -> D
```

系统内部保存为四条路线段：

```text
A -> J
J -> B
J -> C
J -> D
```

这里的 `J` 是内部地图点，保存在 `route_endpoint`。运营不在资产列表中单独管理它，只在路线绘制和端点重设时短暂看到可吸附提示。

## 6. 禁止连接中间路径点

允许连接端点：

```text
A -> J
J -> B
J -> C
```

不允许连接到另一条路线的中间路径点：

```text
A -------- B
     |
     C
```

如果运营需要这种分叉，应显式把原路线重做为：

```text
A -> J
J -> B
J -> C
```

原因：一条路线保存后承载长度、耗时、类型、收费和 AI 描述，不能因为几何上的一次连接被系统自动拆成两条语义不同的路线。

## 7. 景点定位和围栏

景点由两部分组成：

```text
景点 = 标注点 + polygon 围栏
```

规则：

- 新建景点时点击地图，生成标注点和默认 polygon
- 标注点默认在 polygon 几何中心
- 编辑 polygon 顶点后，标注点回到新的几何中心
- 拖动景点标注点时，polygon 整体平移
- 与景点相连的路线端点跟随标注点移动
- 景点 polygon 是自动讲解围栏来源

## 8. 服务点

服务点是点位对象：

```text
服务点 = point + facilityType + description
```

规则：

- 新建服务点时点击地图生成点位
- 默认不可拖动，进入位置编辑后才能拖动
- 拖动服务点后，关联路线端点跟随
- 删除服务点时级联提示关联路线

## 9. 路线创建

创建路线时：

- 第一次点击确定起点
- 中间点击追加中间路径点
- 点击景点、服务点或内部地图点可作为终点
- 空白地图点可以作为起点或终点，但保存路线时才创建内部地图点
- 取消绘制不得留下内部地图点

吸附候选只包括：

- 景点标注点
- 服务点点位
- 已有内部地图点

不包括：

- 另一条路线的中间路径点
- 路线线条本身
- 景点 polygon 边缘
- 高德 POI

## 10. 路线编辑

编辑已有路线分两类：

### 10.1 编辑折线

默认只编辑路线几何形状：

- 可新增中间路径点
- 可拖动中间路径点
- 可删除中间路径点
- 不改变 from/to
- 不改变路线业务属性
- 不创建新的内部地图点

### 10.2 重设端点

只有用户显式点击“重设起点”或“重设终点”时，才允许改变端点引用。

规则：

- 点击景点、服务点或内部地图点时重绑
- 点击空白地图点时保存时创建内部地图点
- 原内部地图点若不再被任何路线引用，保存后清理
- 中间路径点不参与端点重设

## 11. 吸附策略

吸附只发生在两个时机：

1. 创建路线选择起点或终点
2. 显式重设路线起点或终点

算法要求：

- 使用屏幕像素距离判断最近候选
- 阈值控制在小范围内，避免远距离误吸附
- 根据当前 zoom 计算地理距离保险，防止像素转换异常导致飞吸附
- 只高亮当前最近候选
- 不常驻显示大面积吸附圈
- 地图拖动后不落点

## 12. 后端表设计

### 12.1 route_endpoint

内部地图点表：

```sql
CREATE TABLE route_endpoint (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  scenic_area_id BIGINT NOT NULL,
  name VARCHAR(100),
  endpoint_type VARCHAR(32) NOT NULL DEFAULT 'MAP_POINT',
  longitude DECIMAL(10,7) NOT NULL,
  latitude DECIMAL(10,7) NOT NULL,
  status TINYINT DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted TINYINT DEFAULT 0
);
```

### 12.2 route_segment

路线段表：

```sql
CREATE TABLE route_segment (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  scenic_area_id BIGINT NOT NULL,
  name VARCHAR(100) NOT NULL,
  from_type VARCHAR(32) NOT NULL,
  from_id BIGINT NOT NULL,
  to_type VARCHAR(32) NOT NULL,
  to_id BIGINT NOT NULL,
  middle_points JSON NOT NULL,
  length_meter INT,
  duration_min INT,
  route_type VARCHAR(32) NOT NULL DEFAULT 'WALK',
  is_paid TINYINT DEFAULT 0,
  ai_note VARCHAR(1000),
  crowd_level TINYINT,
  status TINYINT DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted TINYINT DEFAULT 0
);
```

## 13. 发布校验

发布校验至少包括：

| 校验 | 级别 |
|------|------|
| 景区默认中心点缺失 | error |
| 景点 polygon 无效 | error |
| 路线缺少起点或终点 | error |
| 路线起终点相同 | error |
| 内部地图点孤立 | warning |
| 景点没有关联路线 | warning |
| 路线长度为空 | warning |
| 路线耗时为空 | warning |
| AI 描述为空 | warning |
| 路线停用或严重拥挤 | warning |

## 14. 给 AI 的数据

AI 路线推荐读取：

- 景点名称、描述、标签、polygon
- 服务点名称、类型、坐标
- 路线段 from/to
- 路线段长度、耗时、类型、收费、拥挤度
- `aiNote` 中的桥、坡、临水、台阶、缆车、适合人群等描述

AI 不直接编造不存在的路。AI 生成推荐前必须基于已发布路线段图谱。

## 15. 前端展示原则

- 普通浏览时只显示景点、服务点、路线
- 内部地图点只在路线绘制、端点重设时短暂显示
- 中间路径点只在编辑折线时显示
- 路线选中高亮，其他路线弱化
- 不展示“拓扑端点”“路线节点”等运营无感概念
- 发布页展示校验分、阻塞项、提醒项、草稿差异和发布记录
