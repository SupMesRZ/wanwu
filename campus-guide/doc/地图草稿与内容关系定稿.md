# 地图草稿与内容关系定稿

> 本文是地图工作台、路线管理、知识库和游客端读取逻辑的开发指引。现有数据库表、接口和 mock 可按本文推翻重做，不要求兼容中间测试阶段设计。

## 1. 总体结论

本项目不做复杂地图版本系统，不做历史版本、归档版本、回滚版本和不可变发布快照。

一个景区可以维护多个地图草稿。每个草稿是一套完整地图方案，包含景点、服务点、路线段、内部地图点、预置路线、地图中心点和默认缩放。

同一景区只能有一个草稿处于 `ONLINE` 状态。游客端只读取 `ONLINE` 草稿。其他草稿都处于 `DRAFT` 状态，可自由编辑。

知识库资料只按景区维护，不绑定景点、服务点、路线或地图草稿。AI 数字人通过景区级 RAG、当前位置上下文和景点名称上下文完成问答和讲解。

## 2. 地图草稿

地图草稿状态只保留两类：

```text
DRAFT：普通草稿，可编辑，可删除，可上线
ONLINE：当前游客端使用草稿，不能删除，物理拓扑锁定
```

同一景区只允许一个 `ONLINE`。

地图草稿包含：

```text
景点
服务点
内部地图点
路线段
预置路线
地图中心点
默认缩放
```

工作台默认加载当前选择的草稿。若没有选择草稿，优先加载 `ONLINE`。若景区没有任何草稿，显示空工作台并允许创建新草稿。

## 3. 编辑规则

`DRAFT` 草稿允许编辑全部内容：

- 新增、编辑、删除景点
- 编辑景点 polygon 围栏
- 新增、编辑、删除服务点
- 新增、编辑、删除路线段
- 新增、编辑、删除内部地图点
- 新增、编辑、删除预置路线
- 修改地图中心点和默认缩放

`ONLINE` 草稿禁止修改物理拓扑：

- 景点坐标
- 景点围栏
- 服务点坐标
- 路线段起点
- 路线段终点
- 路线段中间点
- 内部地图点
- 地图中心点
- 默认缩放

`ONLINE` 草稿允许热更新运营元信息：

- 景点名称、简介、启停状态
- 服务点名称、类型、简介、启停状态
- 路线段名称、长度、耗时、路线类型、收费情况、拥挤度、AI 描述、启停状态
- 预置路线名称、目标序列、描述、预计耗时、适合人群、推荐说明、启停状态

预置路线目标序列虽然可以热更新，但保存或启用时必须通过当前 `ONLINE` 草稿的路线可达性校验。

## 4. 新建草稿

新建草稿提供两个入口：

```text
从已有草稿复制
创建空白草稿
```

从已有草稿复制时，复制景点、服务点、内部地图点、路线段、预置路线、地图中心点和默认缩放。

复制得到的新草稿状态为 `DRAFT`。

创建空白草稿时，景点、服务点、路线段、内部地图点和预置路线均为空，地图中心默认北京或景区默认中心。

为了降低运营丢失风险，`DRAFT` 草稿允许自动保存。建议前端每 1 分钟自动保存一次当前草稿，同时保留手动保存按钮。

## 5. 上线流程

上线就是把某个 `DRAFT` 草稿切换为 `ONLINE`。

上线流程：

```text
1. 运营选择一个 DRAFT 草稿
2. 发布页执行地图校验和预置路线校验
3. 若存在阻塞项，禁止上线
4. 若校验通过，运营确认上线
5. 原 ONLINE 草稿切换为 DRAFT
6. 目标草稿切换为 ONLINE
```

系统不做回滚。若运营想恢复旧方案，直接选择旧草稿重新上线。

## 6. 发布校验

发布校验只检查会影响游客端可用性的内容，不把运营可后补的信息作为阻塞项。

阻塞项：

- 景点坐标缺失
- 景点围栏无效
- 服务点坐标缺失
- 路线段缺少起点或终点
- 路线段起终点相同
- 路线段引用不存在的景点、服务点或内部地图点
- 启用的预置路线引用不存在的景点
- 启用的预置路线相邻景点不可达

非阻塞项：

- 路线长度为空
- 路线耗时为空
- 路线 AI 描述为空
- 景点没有资料
- 景点没有讲解词
- 资料没有绑定景点

预置路线可达性校验复用路线算法模块。路线算法根据当前草稿的路线段拓扑判断两个景点之间是否可达。

## 7. 预置路线

预置路线属于地图草稿的一部分，绑定某个地图草稿，不作为跨草稿的全局对象。

预置路线只绑定景点序列，不绑定底层路线段。

```text
亲子路线：A -> B -> C
```

从 A 到 B、B 到 C 实际怎么走，由路线算法根据当前草稿的物理拓扑计算。

预置路线可维护：

- 名称
- 目标景点序列
- 描述
- 预计耗时
- 适合人群
- 推荐说明
- 启停状态

如果景点被删除，引用该景点的预置路线进入需处理状态。保存或上线时，如果启用的预置路线仍引用不存在的景点，发布校验阻塞。

如果目标景点仍存在但不可达，发布校验阻塞。

路线段长度、耗时和描述由运营维护，允许为空，不作为预置路线校验阻塞项。

## 8. 知识库资料

知识库资料只绑定景区，不绑定景点、服务点、路线或地图草稿。

资料类型第一阶段聚焦文本和可转文本文件：

- 文本
- PDF
- Word
- 可解析文本的其他文件

视频、音频、图片不进入地图草稿，也不绑定地理围栏。后续可提供音频转写、视频字幕提取、图片 OCR 等能力，将多媒体内容转成文本后进入景区级知识库。

游客到达某个位置时，系统通过当前 `ONLINE` 草稿识别附近景点，把景点名称、当前位置和用户问题作为 RAG 上下文，从景区级知识库中检索答案。

资料编辑和地图上线互不影响。

## 9. 游客端读取逻辑

游客端读取：

```text
当前景区 ONLINE 草稿
当前景区启用的知识库
```

游客端展示地图、景点、服务点、路线段和预置路线时，只使用 `ONLINE` 草稿中的数据。

游客端发起讲解或问答时，使用当前位置上下文和景点名称上下文增强 RAG 检索。

游客端不读取 `DRAFT` 草稿。

## 10. 域边界

地图工作台负责：

- 地图草稿
- 景点
- 服务点
- 内部地图点
- 路线段
- 地图上线

路线管理负责：

- 当前草稿下的预置路线
- 预置路线目标景点序列
- 预置路线描述信息
- 预置路线可达性校验调用

路线算法负责：

- 基于当前草稿拓扑判断两个景点是否可达
- 基于当前草稿拓扑计算点到点路线

知识库负责：

- 景区级资料上传
- 文档解析
- 文档切片
- 向量化
- FAQ
- RAG 检索

知识库不负责地图对象绑定，不参与地图草稿状态切换。

## 11. 数据和接口重做原则

现有数据库和接口可以推翻重做，不要求兼容中间测试阶段设计。

新的接口设计应围绕以下资源：

```text
地图草稿
草稿工作台数据
草稿上线
预置路线
景区级知识库资料
```

不要继续引入：

- 历史版本
- 回滚
- 归档版本
- 不可变发布快照
- 资料绑定景点
- 资料绑定地图版本
- 预置路线绑定路线段

开发实现以本文为准。
