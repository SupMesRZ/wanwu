> **P1-5 / P1-6 完成说明**（2026-07-26，基线 `mvn test` 190 通过 / `vite build` 通过）：
>
> 1. **权限码不入库**。初版计划里的 `sys_permission` 表被否掉了：权限码的唯一意义是"某个接口会校验它"，能在后台自由增删的权限码只是空壳，还会和代码里的注解对不上。最终权限码定义在 `system.security.PermissionCode` 枚举（16 个，按 7 个模块分组），后台只读展示、只做勾选；**角色才是数据**，落在 `sys_role` + `sys_role_permission` + `sys_user_role` 三张表。两张关联表用物理删除——逻辑删除会让"取消勾选后重新勾选"撞上唯一键。
> 2. **权限集不进 Token**。JWT 里只有身份，权限集每次请求按 userId 查（Redis 缓存 + DB 兜底），改授权立刻生效，不必等 Token 过期或强制下线。
> 3. **两层门槛**。`@RequireAdmin` 管粗粒度"是不是后台用户"，`@RequirePermission` 叠在上面管细粒度；后者刻意**不参与**"方法级注解覆盖类级"的判定，否则方法上的权限码会把类上的 `@RequireAdmin` 顶掉。切面内另有一道 `role == ADMIN` 复核：游客和管理员的 userId 来自不同的表，数字会撞车，不复核就等于把管理员的权限借给了同号游客。
> 4. **角色与账号的写操作仍限 root**。"能改角色"和"能建账号并给它配角色"都等价于"能给自己加任意权限"，这条提权路径只留给 root；读操作才下放给 `system:role:manage` / `system:user:manage`。
> 5. **内置角色开机自动补种**（系统管理员 16 项 / 内容运营 10 项 / 只读观察员 7 项），只在角色标识缺失时补，不覆盖管理员已调整的勾选；补种失败只告警不阻断启动——root 账号本身不依赖角色。
> 6. **菜单只是回显**。前端菜单按 `GET /admin/users/me` 下发的权限码过滤，纯粹为了少让人点到 403；真正的门在切面上。顺带修掉了登录页把 `admin_is_root` 硬编码成 `true` 的老问题。
> 7. 三张表的 DDL 本就写在 `sql/init.sql`，但**远程 `group_db` 未执行**，已补建。
> 8. **测试全部落在离线层**。新增 34 条：`AuthAspectPermissionTest`（切面判定，自造 JoinPoint，不起容器）、`UserPermissionServiceTest`（聚合链路与缓存）、`RoleServiceTest`（角色约束），加上 `AdminUserServiceTest` 的角色分配补充。三个新类总耗时约 2 秒，符合 `产品架构与功能设计.md` §4.5 对"权限判定进离线单测层"的要求，不必等 P2-1 重构。被钉住的关键行为：root 直通不查权限集、多权限码为"任一满足"、`@RequirePermission` 不顶掉类级 `@RequireAdmin`、同号游客借不到管理员权限、停用角色不授权、缓存空串≠未命中、陌生权限码不落库、内置角色与在用角色不可删。

> **P1-10 完成说明**：初版评审误判"无 Dijkstra 实现"，实际算法一直在 `ScenicTopologyPathService`。真正的缺口是三个权重配置从未被读取，且选路代价与上报里程混用同一个累计值。本项已修复两者，详见 `产品架构与功能设计.md` §4.4 的定档说明。

> **P1-7 完成说明**（2026-07-27，基线 `mvn test` 222 通过 / `vite build` 通过）：
>
> 1. **自动兜底 + 注解增强**。`OperationLogAspect` 捕获 `/api/v1/admin/**` 下全部非 GET 请求，审计完整性由结构保证——新接口忘了标注也照样进日志。`@OperationLog` 只做可选增强：中文模块名/动作名（缺失时取 Swagger `@Tag` → 类名、方法名前缀 → HTTP 方法逐级推导）、`withoutParams`、`ignore`，以及把登录这类非 admin 前缀接口拉入记录范围。
> 2. **切面排在 `AuthAspect` 外层**（`@Order(1)` 对无 `@Order` 的最低优先级）：越权被拒的请求以异常形式穿过日志切面，记成 FAILURE。"谁试图删了不该删的东西"比成功记录更有审计价值。
> 3. **参数落库前必过三道**：跳过不可序列化的容器对象（`ServletRequest` 用 `instanceof` 判，包名比对会漏掉 `RequestFacade`）、递归按字段名脱敏（密码/验证码/密钥全打码，手机号保头尾）、按配置截断（默认 2000 字符，防地图草稿类大 payload 把审计变成事故源）。
> 4. **审计绝不弄坏业务**：组装与落库两级 try/catch 吞异常只告警，开关读不到默认继续记，同步写入（后台写是人工点击频率，一条索引化 INSERT 远比会丢记录的异步队列可靠）。
> 5. **无增长上限问题有解**：`@EnableScheduling` + 每日 03:20 定时任务按 `ops-operation-log-retention-days`（默认 90 天）物理删除；**配成 0/负数视为永久保留不删**，避免误配清空审计。表刻意不带 `deleted`——日志只追加，逻辑删除等于永不释放磁盘。
> 6. **日志只读不可改**：查询页没有编辑接口是有意的，能改的审计记录等于没有审计；唯一的写操作"立即清理"限 root。读权限下放给新增的 `system:log:read`（第 17 个权限码）。
> 7. 远程 `group_db` 已补建 `sys_operation_log`（含 `created_at`/`user_id`/`module` 三索引）。新增 32 条离线单测：脱敏/截断/模块推导/动作推导/FAILURE 记录/开关关闭/非 admin 不记/保留期误配不删/IP 解析。
