## 1. 一句话结论

**核心 AI 导览链路（问答、流式输出、TTS 播报、Live2D 数字人、地图工作台、围栏）是真实可用的工程实现，质量在 MVP 之上；但"完整产品"的外围有大面积空缺——语音输入完全不存在、管理后台有 6 个页面是纯前端假数据、7 条路由指向占位页、system 域承诺的 RBAC/操作日志/限流三件套均无实现。**

项目不是"差最后一公里"，而是**中间有一段真空**：底座扎实，前台可跑，中台缺失。

## 5. 前后端契约核对结论

### 5.1 澄清：QA 页面契约是正确的

`QaResourcePage.vue` 使用 `/admin/qa/faqs`、`/admin/qa/knowledge-docs` 等路径，**与后端完全一致**。这四个页面（知识库 / 切片 / FAQ / 讲解词）是可用的，只是被占位页挡住了入口。

### 5.2 死代码：三个未挂载的旧版页面

`views/Assets.vue`、`views/FAQ.vue`、`views/Knowledge.vue` 调用 `/admin/spots`、`/admin/faqs`、`/admin/knowledge-docs`、`/admin/tags` 等**过时路径**，但均**未注册到路由**，属于被 `QaResourcePage` / `MapWorkbench` 取代后的遗留。`FAQ.vue` 内甚至硬编码了三条"景区代步工具 / 无人机航拍"的演示数据写入逻辑。

**处置：删除。** 保留只会持续误导契约审计。

### 5.3 真实断裂：一处

| 页面 | 路由 | 调用 | 后端 |

## 6. 三个系统性问题

### 6.1 【P0】管理后台有 6 个页面是纯前端假数据

`GenericAdminPage.vue` 的数据源是 `resourceConfigs.js` 里的 `seedRows` 硬编码数组：

```js
rows.value = config.value.seedRows.map(item => ({ ...item }))
```

**全部增删改查都只操作内存数组并弹出成功提示**，无任何 HTTP 请求：

```js
const handleDelete = async (row) => {
  await ElMessageBox.confirm(...)
  rows.value = rows.value.filter(item => item.id !== row.id)
  ElMessage.success('删除成功')   // 骗人的
}
```

受影响路由：`/scenic/tags`、`/system/roles`、`/system/permissions`、`/system/logs`、`/system/rate-limits`、`/system/configs`

`resourceConfigs.js` 共 696 行，为 20+ 种资源编造了云山古镇 / 望月桥 / 湖畔湿地等虚构数据。

> **危害等级最高**：这些页面**看起来完全正常**——能搜索、能新增、能删除、能弹成功提示。演示时无人能察觉，刷新后数据复原。对"商用产品"而言这是不可接受的，必须**要么接真后端，要么下架入口**，绝不能保持现状。
>
> 顺带说明：`/system/configs` 尤其讽刺——后端配置中心（6 个接口）是真实可用的，前端却在读假数据。

### 6.2 【P0】路由回归：7 条路由被改回占位页

提交 `a486d28 refactor(frontend): 重构前端路由和界面结构` 将以下路由指向 `Placeholder.vue`，而**对应的真实页面文件仍然存在且可用**（约 1600 行）：

| 路由 | 被弃用的真实页面 |
|------|------|
| `/scenic/areas` | `scenic/AreaList.vue`（465 行） |
| `/routes/config` | 无对应页面，需新建 |
| `/qa/knowledge-docs` | `qa/KnowledgeDocList.vue` → `QaResourcePage` |
| `/qa/knowledge-chunks` | `qa/KnowledgeChunkList.vue` → `QaResourcePage` |
| `/qa/faqs` | `qa/FaqList.vue` → `QaResourcePage` |
| `/qa/guide-scripts` | `qa/GuideScriptList.vue` → `QaResourcePage` |
| `/analytics/dashboard` | `analytics/AnalyticsDashboard.vue`（453 行） |

`MVP-验收报告.md`（2026-06-30）明确记录曾验证 `#/qa/faqs` 展示真实 FAQ 数据、`#/analytics/*` 正常——**这些功能确实做过、确实能用，是被重构误伤的**。已确认为回归，须恢复。

### 6.3 【P1】测试体系无法运行

125 个用例中 49 个 error，根因单一：

```
RedisConnectionFailureException: Unable to connect to Redis
  → io.lettuce.core.RedisConnectionException: localhost/<unresolved>:6379
    → java.net.ConnectException: Connection refused
```

这不是代码缺陷，是**测试架构问题**：全部用例都是 `@SpringBootTest` 集成测试，强耦合活的 MySQL（远程 `120.26.20.226`）、Redis、Qdrant、LLM、TTS。

后果：
- 没有任何一个用例能在无网络 / 无中间件的环境跑（无法进 CI）
- 单元测试层完全缺失，纯逻辑（围栏状态机、坐标转换、路线校验）也要起 Spring 容器
- 远程 MySQL 一旦不可达，全量测试直接瘫痪

## 9. 值得肯定的部分

避免评审只谈问题，以下模块质量确实在线，重构时**不要动**：

1. **地图工作台**（scenic）——草稿/发布/上线三态 + 生成列唯一约束保证同景区仅一个 ONLINE 版本，是全项目设计最好的模块
2. **围栏状态机**（tourist）——`OUTSIDE/ENTERING/INSIDE/COOLDOWN/EXITED` + 精度过滤 + 跳点过滤 + 冷却去重，考虑了真实 GPS 的脏数据
3. **SSE 流式链路**——Reactor 用法规范，`boundedElastic` 调度与 `doFinally` 清理到位
4. **配置中心模式**——各域 `ConfigProperties` + `ConfigInitializer` + 统一 CRUD 入口，职责切分清晰
5. **Agent 路线校验**——`createTourRoute()` 强制节点必须来自已发布地图版本，杜绝 LLM 编造景点，符合 PRD §6.1

## 10. 结论

| 判断 | 结论 |
|------|------|
| 核心链路是否跑通 | ✅ 是（问答 / 流式 / TTS / Live2D / 地图 / 围栏） |
| 是否"功能完整" | ❌ 否，缺 ASR、消息历史、RBAC、操作日志、限流、标签、词云、情感分析、算路 |
| 是否需要重构 | ⚠️ 局部需要：route 域重建、测试分层、假数据页面处置、域边界纠偏 |
| 距离商用 | 三个阶段，详见 `商用化路线图.md` |

**最需要立刻纠正的认知**：项目不是"差临门一脚"。管理后台有 6 个页面在演假数据、7 条路由指向占位页、语音输入从未实现——这些在演示中都不会暴露，但任何真实用户接触后立刻穿帮。
