# 接口规范与文档

## 1. 通用规范

所有接口返回 `ApiResponse<T>`：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "traceId": "trace-id"
}
```

分页接口 `data` 为 `PageResponse<T>`：

```json
{
  "records": [],
  "page": 1,
  "pageSize": 20,
  "total": 0,
  "totalPages": 0
}
```

URL 前缀：

| 前缀 | 说明 | 认证 |
|------|------|------|
| `/api/v1/tourist/**` | 游客端接口 | 可匿名，部分需 Bearer |
| `/api/v1/admin/**` | 管理后台接口 | JWT Bearer Token + Admin |
| `/api/v1/system/**` | 系统公共接口 | 视接口而定 |

HTTP 方法：

| 方法 | 用途 |
|------|------|
| GET | 查询 |
| POST | 创建或领域动作 |
| PUT | 全量更新或保存草稿 |
| PATCH | 局部更新或状态变更 |
| DELETE | 逻辑删除 |

## 2. 当前地图草稿模型

地图工作台对接地图草稿。一个景区可以有多个草稿，同一景区最多一个草稿为 `ONLINE`。

```json
{
  "scenicAreas": [],
  "currentArea": {},
  "currentDraft": {},
  "drafts": [],
  "payload": {
    "mapCenter": [39.9042, 116.4074],
    "defaultZoom": 16,
    "spots": [],
    "facilities": [],
    "routeEndpoints": [],
    "routeSegments": [],
    "presetRoutes": []
  }
}
```

`DRAFT` 草稿允许完整编辑。`ONLINE` 草稿禁止修改物理拓扑，但允许热更新名称、描述、启停状态、路线长度、耗时、收费、拥挤度、AI 描述和预置路线描述等运营元信息。

## 3. 管理后台地图接口

### 3.1 查询默认地图草稿

```text
GET /api/v1/admin/map-drafts
```

响应：`ApiResponse<List<ScenicMapDraftResponse>>`

```json
[
  {
    "id": 1,
    "scenicAreaId": 1,
    "name": "上线地图",
    "status": "ONLINE",
    "lastSavedAt": "2026-06-15T10:00:00"
  }
]
```

### 3.2 创建默认地图草稿

```text
POST /api/v1/admin/map-drafts
```

请求体：

```json
{
  "name": "新地图草稿",
  "copyFromDraftId": 1
}
```

当前阶段暂不开放多景区。后端会自动使用默认景区“桃花源”作为内部上下文，`copyFromDraftId` 为空时创建空白草稿；不为空时复制已有草稿。

### 3.3 获取地图草稿工作台数据

```text
GET /api/v1/admin/map-drafts/{draftId}/workbench
```

响应：`ApiResponse<MapWorkbenchResponse>`

### 3.5 删除地图草稿

```text
DELETE /api/v1/admin/map-drafts/{draftId}
```

`ONLINE` 草稿不能删除。

### 3.6 地图草稿上线校验

```text
GET /api/v1/admin/map-drafts/{draftId}/publish-check
```

响应：`ApiResponse<MapPublishResponse>`

### 3.7 上线地图草稿

```text
POST /api/v1/admin/map-drafts/{draftId}/publish
```

请求体：

```json
{
  "note": "发布云山古镇地图配置"
}
```

上线语义：

- 基于 `draftId` 对应草稿执行校验
- 存在阻塞校验时拒绝发布
- 上线后目标草稿变为 `ONLINE`，原 `ONLINE` 草稿变为 `DRAFT`
- 游客端地图、路线高亮、围栏触发和 AI 推荐读取新的 `ONLINE` 草稿

## 4. 管理后台路线段接口

### 4.1 查询路线段列表

```text
GET /api/v1/admin/scenic-areas/{areaId}/route-segments
```

响应：`ApiResponse<List<RouteSegmentResponse>>`

### 4.2 创建路线段

```text
POST /api/v1/admin/scenic-areas/{areaId}/route-segments
```

请求体：`RouteSegmentRequest`

```json
{
  "name": "东入口 - 民俗馆",
  "from": { "type": "SPOT", "id": 1 },
  "to": { "type": "SPOT", "id": 2 },
  "middlePoints": [
    { "longitude": 120.138, "latitude": 30.2524 }
  ],
  "lengthMeter": 520,
  "durationMin": 8,
  "routeType": "WALK",
  "paid": false,
  "aiNote": "平整石板路，适合亲子和老人慢行",
  "crowdLevel": 1,
  "status": 1
}
```

当端点是空白地图点时：

```json
{
  "type": "ENDPOINT",
  "longitude": 120.14148,
  "latitude": 30.25358
}
```

后端会在创建/更新路线时物化 `route_endpoint`。

### 4.3 更新路线段

```text
PUT /api/v1/admin/route-segments/{segmentId}
```

请求体同创建路线段。

规则：

- `from` 和 `to` 必填
- 端点类型只允许 `SPOT`、`FACILITY`、`ENDPOINT`
- 头尾不能指向同一个端点
- `middlePoints` 只保存几何控制点，不参与端点引用
- 编辑折线不得隐式拆分路线

### 4.4 删除路线段

```text
DELETE /api/v1/admin/route-segments/{segmentId}
```

删除路线后，后端清理不再被任何路线引用的内部地图点。

### 4.5 查询对象关联路线

```text
GET /api/v1/admin/scenic-areas/{areaId}/route-segments/related?targetType=SPOT&targetId=1
```

`targetType` 可选：`SPOT`、`FACILITY`、`ENDPOINT`

用于删除景点或服务点前展示级联影响。

### 4.6 路线拓扑校验

```text
GET /api/v1/admin/scenic-areas/{areaId}/route-topology/validations
```

响应：`ApiResponse<RouteTopologyValidationResponse>`

校验项：

- 路线引用对象是否存在
- 路线头尾是否相同
- 路线长度、耗时、AI 描述是否完整
- 内部地图点是否孤立或只有单边连接
- 景点是否没有关联路线

## 6. 游客端接口

### 6.1 景区基础数据

```text
GET /api/v1/tourist/scenic-areas/{areaId}
GET /api/v1/tourist/scenic-areas/{areaId}/spots
GET /api/v1/tourist/scenic-areas/{areaId}/facilities
GET /api/v1/tourist/scenic-areas/{areaId}/map
```

游客端地图接口读取当前 `ONLINE` 地图草稿。景点 polygon 可用于自动讲解判定，但游客端无需直接展示 polygon。

### 6.2 会话和位置

```text
GET  /api/v1/tourist/session/init
POST /api/v1/tourist/session/create
POST /api/v1/tourist/session/{id}/message
POST /api/v1/tourist/session/{id}/location
GET  /api/v1/tourist/session/{id}/route
POST /api/v1/tourist/session/{id}/close
```

位置上报触发景点 polygon 判定，产生围栏触发日志和自动讲解。

### 6.3 路线

```text
GET  /api/v1/tourist/routes
GET  /api/v1/tourist/routes/{id}
POST /api/v1/tourist/routes/path
POST /api/v1/tourist/routes/ai-recommend
```

路线计算基于已发布的 `route_segment` 图谱。

## 7. 预制路线目标编排

预制路线后台不暴露底层内部地图点排序，而是编排游览目标：

```text
PUT /api/v1/admin/routes/{id}/targets/order
```

请求体：

```json
{
  "targetSequence": [
    { "type": "SPOT", "id": 1 },
    { "type": "FACILITY", "id": 2 },
    { "type": "SPOT", "id": 3 }
  ]
}
```

## 8. 配置接口

普通配置统一走 system 配置中心：

```text
GET /api/v1/admin/configs/domains/{domain}
PUT /api/v1/admin/configs/domains/{domain}/{key}
PUT /api/v1/admin/configs/domains/{domain}/batch
```

route 域当前配置键：

- `route-dijkstra-weight-distance`
- `route-dijkstra-weight-duration`
- `route-dijkstra-weight-crowd`
- `route-ai-prefer-tags`
- `route-max-targets`

scenic 域当前配置键：

- `scenic-fence-default-radius`
- `scenic-fence-default-cooldown`
- `scenic-fence-threshold-meters`
