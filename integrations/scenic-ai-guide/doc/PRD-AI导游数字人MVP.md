# AI 导游数字人 MVP PRD

## 1. 产品定位

本项目一期面向真实景区上线使用，不按展示型 Demo 设计。MVP 目标是在一个示例景区内打通后台内容配置、地图版本发布、AI 导游数字人交互、定制路线推荐、地理围栏自动讲解、TTS 语音播报的完整闭环。

游客端的产品核心不是地图导航页，而是一个对话式 AI 导游数字人 Agent。地图、景区拓扑、路线、知识库、地理围栏和 TTS 都是数字人 Agent 的工具能力。

一期不做多租户。未来商业化多租户方向为：平台给会员公司开通专属链接和账号，游客进入专属链接后看到该公司自己的景区数字人，数据、配置、知识库和会话互不干扰。

## 2. 角色范围

一期角色只包含：

- 游客：通过移动端 H5 与 AI 导游数字人交互，获取路线、问答、讲解和语音播报
- 管理员：维护示例景区地图、路线、知识库、FAQ、讲解词和数字人配置
- Root：平台最高权限账号，用于初始化和高级管理

一期不拆分运营人员、内容编辑、景区工作人员等细粒度角色。

## 3. MVP 核心目标

一期必须完成以下闭环：

1. 管理员能登录后台
2. 管理员能维护并发布一份线上地图版本
3. 管理员能维护路线节点、路段、路线模板、景点和服务点
4. 管理员能维护 FAQ、知识文本、讲解词，并让游客问答可用
5. 管理员能配置数字人名称、头像、人设、欢迎语、音色、语速和动作状态
6. 游客打开移动端 H5 后看到数字人导游，能文字对话
7. Agent 能根据游客偏好生成本次会话专属 AI 路线
8. 游客定位进入景点围栏并满足停留条件后，自动触发讲解和 TTS 播报

## 4. 游客端体验

### 4.1 主界面

游客端采用移动端 H5。第一屏以数字人导游为主，地图和路线作为辅助面板展示，可展开全屏地图。

主界面包含：

- 数字人头像或形象
- 数字人名称和当前动作状态
- 对话消息列表
- 文字输入框
- 语音播报控制
- 当前路线进度摘要
- 小地图或地图入口
- 附近景点和服务点提示

数字人动作状态一期至少包含：

- `idle`：待机
- `listening`：聆听
- `thinking`：思考
- `speaking`：播报
- `error`：异常

### 4.2 开场引导

游客进入后，数字人主动欢迎并一次性引导游客表达偏好。不能反复多轮盘问游客。

建议开场语：

> 欢迎来到桃花源，我是你的 AI 导游。你可以直接问我景点故事、厕所餐饮位置，也可以告诉我游览时长、同行人群和兴趣偏好，我会为你安排一条适合今天的路线。

偏好采集字段：

- 游览时长
- 同行人群
- 兴趣偏好
- 体力强度
- 无障碍或少台阶需求
- 服务点偏好，如厕所、餐饮、出口

如果游客没有提供偏好，只说“开始游览”，Agent 使用默认策略推荐路线。

### 4.3 AI 问答边界

景区事实类问题必须严格基于 FAQ、讲解词和知识库回答。没有依据时不能编造，应明确说明当前资料不足，并给出安全引导。

允许闲聊，但闲聊不能编造景区事实、价格、开放时间、安全规定、历史传说等可造成商业风险的信息。

问答优先级：

1. FAQ 精确或高置信命中
2. 知识库 RAG 检索
3. 大模型基于检索上下文组织答案
4. 无依据时安全拒答或引导

## 5. AI 导游 Agent

### 5.1 Agent 定位

Agent 是游客端导览能力的核心编排层。它不直接拥有所有业务数据，而是通过工具调用景区拓扑、路线、QA、数字人、游客会话等能力。

### 5.2 工具能力

一期工具清单：

- 获取线上地图拓扑
- 查询当前位置附近景点
- 查询当前位置附近服务点
- 查询路线模板
- 生成受约束 AI 路线
- 查询当前导览会话状态
- 更新当前路线和节点状态
- FAQ 检索
- RAG 检索
- 获取景点讲解词
- TTS 语音合成
- 记录消息和播报日志

### 5.3 安全约束

Agent 不能凭空生成不存在的景点、路段、入口、出口、服务点或景区事实。所有路线和讲解内容必须来自已发布地图版本、后台路线素材、FAQ、讲解词或知识库。

如果工具不可用、知识不足、地图未发布或路线素材不足，Agent 必须明确说明限制。

## 6. 路线能力

### 6.1 路线生成原则

一期采用“基于预制路线素材的个性化组合”。

后台维护：

- 已发布地图拓扑
- 景点
- 服务点
- 路线节点
- 路段
- 路线模板

Agent 可以根据游客偏好组合游客本次专属路线，但必须满足：

- 节点必须来自已发布地图版本
- 路段必须来自已发布地图版本
- 组合必须符合后台允许的拓扑关系
- 生成后保存为游客当前会话的 AI 路线
- 没有预制路线素材时，不临时生成路线
- 没有足够偏好时，优先经典模板，其次高热度路线，最后借鉴预制路线

### 6.2 推荐说明

路线推荐必须给出自然语言推荐理由。例如：

> 我给你安排一条 60 分钟轻松路线，先从东入口到民俗馆，再去望月桥拍照，最后到餐饮休息区。路线避开了较长上坡，适合带老人慢慢走。

如果游客偏好和素材冲突，数字人应说明限制，并给最接近方案。

### 6.3 偏离路线

MVP 不做强制导航。游客偏离路线时，Agent 温和提醒：

> 你现在离推荐路线有点远，要继续自由游览，还是我帮你回到路线？

## 7. 地理围栏自动讲解

### 7.1 设计原则

围栏触发不能采用“定位点进入围栏立刻播报”的简单规则。定位漂移、边界抖动和重复进出都会造成误触发。

一期采用服务端状态机，参考成熟地理围栏平台的 ENTER、DWELL、EXIT 语义。讲解触发使用 DWELL 语义，即游客进入并停留稳定后才播报。

### 7.2 定位点过滤

定位点需包含：

- 经度
- 纬度
- 定位时间
- 精度 accuracy
- 速度 speed，可选

过滤规则：

- accuracy 过差的定位点不参与关键触发
- 明显跳点不参与围栏状态推进
- 时间倒序或过旧定位点丢弃
- H5 前台定位为 MVP 支持范围，不承诺锁屏后台持续触发

### 7.3 状态机

每个会话和每个景点维护独立围栏状态：

- `OUTSIDE`：围栏外
- `ENTERING`：疑似进入
- `INSIDE`：稳定在围栏内
- `COOLDOWN`：已触发冷却中
- `EXITED`：确认离开

触发条件：

- 连续 N 次定位命中围栏，或累计停留时间达到阈值
- 距离上次触发超过景点冷却时间
- 当前会话没有正在播放冲突讲解
- 景点状态允许自动讲解

退出条件：

- 连续 N 次定位在围栏外
- 或距离围栏边界超过退出缓冲距离

默认建议：

- 连续命中次数：2 到 3 次
- 停留阈值：10 到 20 秒
- 退出缓冲：围栏半径或边界外增加 10 到 20 米
- 同景点冷却：30 分钟

具体阈值应放入业务配置或数字人导览配置，但开发阶段可以使用默认值。

### 7.4 触发日志

每次围栏判定应记录必要日志，便于后续调参：

- 会话 ID
- 景点 ID
- 定位点
- accuracy
- 判定结果
- 状态迁移
- 是否触发讲解
- 未触发原因

## 8. 数字人和 TTS

### 8.1 数字人配置

后台一期支持配置：

- 数字人名称
- 头像 URL
- 人设提示词
- 欢迎语
- 默认语音
- 音色
- 语速
- 音量
- 语调
- 动作状态资源

### 8.2 阿里云 TTS 约束

TTS 采用阿里云能力。后台配置不能让管理员任意填写音色、格式、采样率等参数，必须基于阿里云官方文档和当前 SDK 支持范围做枚举、校验和默认值。

实现时必须查阅阿里云官方文档确认：

- voice 音色列表
- format 支持范围
- sampleRate 支持范围
- speechRate 范围
- pitchRate 范围
- volume 范围
- 普通文本合成长度限制
- 长文本合成和流式合成边界

如果供应商 key、应用 key、网络或服务不可用，应将目标标记为受阻并说明外部依赖问题。

## 9. 后台功能

### 9.1 地图工作台

地图工作台是项目核心模块。MVP 继续以已发布地图版本作为游客端唯一数据源。

后台能力：

- 维护景区基础信息
- 维护景点
- 维护服务点
- 维护路线节点
- 维护路线线段
- 维护预制路线或路线模板
- 保存草稿
- 发布线上版本
- 游客端只读取线上版本

### 9.2 路线管理

建议后台单独提供路线模板页面。拓扑点线仍在地图工作台维护，路线模板负责业务语义。

路线模板字段建议：

- 路线名称
- 主题
- 适合人群
- 兴趣标签
- 体力强度
- 预计时长
- 预计距离
- 推荐理由
- 节点顺序
- 是否默认路线
- 状态

### 9.3 QA 管理

后台支持：

- FAQ 管理
- 知识文本管理
- 文本切片
- 向量化
- 检索验证
- 讲解词管理

文档上传解析可后置。MVP 优先保证结构化文本可维护、可向量化、可检索。

### 9.4 数字人管理

后台支持：

- 数字人基础资料
- 头像和动作状态资源
- 人设和欢迎语
- 阿里云 TTS 参数
- 语音试听

## 10. 技术实施约束

开发阶段约束：

- 不做旧数据兼容
- 改表和字段可以直接调整，旧数据可删除或重建
- 改代码前必须充分调研现有实现
- 优先复用或升级旧组件，不为单一功能堆大量兼容函数
- 保持代码整洁，按业务域拆分职责
- 可以在开发阶段设置必要后门辅助本地实测，例如验证码绕过
- 供应商配置、API key、真实 TTS 等外部依赖不可用时，及时标记目标受阻

## 11. 领域职责

建议职责划分：

- `tourist`：游客身份、会话、消息、位置、围栏状态、当前路线和导览状态
- `route`：路线模板、AI 路线实例、拓扑算路、受约束路线组合
- `qa`：FAQ、知识库、RAG、讲解词、问答安全边界
- `digitalhuman`：数字人配置、TTS、播报状态、语音缓存
- `scenic`：景区资产、地图草稿、发布版本、拓扑数据
- `analytics`：运营统计，只读分析，不反向修改业务数据
- `system`：认证、授权、配置中心、通用基础设施

## 12. 验收标准

MVP 完成标准：

1. 后台管理员可以登录
2. 后台可以维护并发布线上地图
3. 后台可以维护路线模板
4. 后台可以维护 FAQ、知识文本和讲解词
5. 后台可以配置数字人基础资料和 TTS 参数
6. 游客可以打开移动端 H5 并看到数字人导游
7. 游客可以用文字提问并获得安全回答
8. 游客可以获得一条基于偏好的本次会话专属路线
9. 游客位置进入围栏并稳定停留后自动触发讲解
10. 数字人可以播放 TTS 语音
11. 无知识依据时 AI 不编造景区事实
12. 地图未发布、路线素材不足、TTS 不可用等异常有明确提示
